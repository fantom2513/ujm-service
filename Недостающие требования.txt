НЕДОСТАЮЩИЕ ТРЕБОВАНИЯ

В этом файле остались только вопросы, которые нужно закрыть для полностью рабочего сервиса. Вопросы, которые можно временно задать через переменные окружения или конфигурацию, не считаются причиной откладывать начало разработки.

Данные, необходимые для подключения внешних сервисов

1. Доступ к Jira и Confluence

Нужно определить:

- адреса корпоративных Jira и Confluence;
- способ серверной авторизации;
- где backend должен брать учетные данные;
- какие типы ссылок поддерживаются;
- какие страницы или задачи сервис имеет право читать.

Без этих данных нельзя полностью реализовать рабочий источник "Ссылка на Jira или Confluence". Остальные источники можно реализовывать независимо.

2. Данные для подключения OpenAI

Нужно определить:

- через какую переменную окружения передается API-ключ;
- какие модели используются для генерации Mermaid;
- какие модели используются для редактирования схемы через чат;
- какие модели используются для транскрибации записей;
- какие лимиты и таймауты применяются к запросам.

Модели, лимиты и таймауты можно временно задать через конфигурацию. Реальные секреты не должны попадать в код.

3. Утвержденный промпт редактирования Mermaid через чат

Промпт первоначальной генерации Mermaid уже предоставлен в PDF и не является недостающим требованием.

Для AI-чата в ТЗ отдельно указан системный промпт редактирования, но его текст не предоставлен.

Без утвержденного промпта редактирования нельзя считать изменение схемы через чат реализованным по финальной бизнес-логике. При этом frontend, API, проверку Mermaid и временную техническую заглушку для интеграции можно готовить заранее.

Технические настройки, которые можно временно задавать через конфигурацию

4. Максимальная продолжительность записи встречи

Размер записи ограничен 100 МБ, но максимальная длительность не указана.

До финального решения можно задать технический лимит через конфигурацию backend и показывать пользователю только утвержденные состояния ошибок.

5. Ограничения текстовых полей

Нужно определить максимальную длину:

- ссылки Jira или Confluence;
- поля дополнительных деталей;
- сообщения в AI-чате.

До финального решения можно задать безопасные технические лимиты через конфигурацию frontend и backend.

6. Требования к мобильной или адаптивной версии

Нужно подтвердить, должен ли сервис полноценно работать на мобильных устройствах и планшетах или достаточно версии по предоставленным Figma-макетам.

До финального решения можно начинать реализацию по Figma и закладывать аккуратное поведение интерфейса на разных ширинах экрана без создания новых визуальных состояний.

7. Механизм автоматического исправления Mermaid

ТЗ требует одну автоматическую попытку исправления Mermaid.

Нужно определить, используется ли отдельный системный промпт исправления или тот же промпт генерации с дополнительной серверной инструкцией.

До финального решения этот механизм можно вынести в конфигурацию backend.

8. Правила production-логов

ТЗ запрещает выводить полное ТЗ и транскрипты в production-логи.

Нужно определить, какие обезличенные служебные события можно логировать для диагностики.

До финального решения можно включить минимальные логи без пользовательского содержимого.

9. Адрес основной страницы продукта

ТЗ требует переход "На главную" по заранее заданному адресу, но сам адрес не указан.

Адрес можно задать через переменную окружения или конфигурацию без изменения кода.
