Задача: реализовать полное редактирование, проверку, вложения и восстановление Mermaid-схемы в AI-чате Copilot UJM.

Сначала изучи существующий код проекта и повторно используй уже реализованные:
- sessionStorage/session-state;
- загрузку файлов;
- извлечение текста;
- обработку табличных файлов;
- транскрибацию аудио и видео;
- Mermaid renderer;
- API-клиент AI;
- компоненты чата и быстрых действий.

Не переписывай несвязанные части приложения.

ИСПОЛЬЗУЙ ГОТОВЫЕ ФАЙЛЫ

Размести и подключи:
- backend/src/prompts/generateMermaid.prompt.txt
- backend/src/prompts/editMermaid.prompt.txt
- backend/src/prompts/repairMermaid.prompt.txt

Также используй правила:
- mermaidValidation.rules.txt

Не сокращай и не переписывай системные промпты без необходимости.

1. КОНТРАКТ РЕДАКТИРОВАНИЯ

Добавь actionType:
- GROUP_SEMANTIC_BLOCKS
- SIMPLIFY
- HIGHLIGHT_MAIN_PATH
- FREEFORM
- RESTORE_PREVIOUS

Backend должен передавать:
- исходное нормализованное ТЗ;
- дополнительные детали;
- текущий валидный Mermaid-код;
- предыдущий валидный Mermaid-код, если он есть;
- actionType;
- сообщение пользователя;
- безопасно извлечённый контекст вложения, если он есть.

2. БЫСТРЫЕ ДЕЙСТВИЯ

Свяжи кнопки:
- «Разбить схему на смысловые блоки» → GROUP_SEMANTIC_BLOCKS
- «Упростить схему» → SIMPLIFY
- «Выделить основной путь» → HIGHLIGHT_MAIN_PATH

При нажатии кнопки:
- добавить пользовательское сообщение в чат;
- отправить явный actionType;
- заблокировать повторную отправку;
- после успешного ответа обновить схему и показать только message.

Не определяй быстрое действие только по тексту кнопки.

3. ОБЫЧНЫЕ СООБЩЕНИЯ

Обычный текстовый запрос получает actionType FREEFORM.

Исключение: до вызова модели распознавай явные команды восстановления:
- «верни предыдущую версию»;
- «верни прошлую схему»;
- «отмени последнее изменение»;
- близкие однозначные формулировки.

Для них используй RESTORE_PREVIOUS.

4. ВОССТАНОВЛЕНИЕ ПРЕДЫДУЩЕЙ ВЕРСИИ

Реализуй детерминированно, без AI-запроса:

Если previousMermaid существует и валиден:
1. поменять местами currentMermaid и previousMermaid;
2. перерисовать восстановленную схему;
3. добавить в чат message:
   «Предыдущая версия схемы восстановлена».

Если previousMermaid отсутствует:
- схему не менять;
- добавить message:
  «Предыдущая версия схемы недоступна».

Prompt с RESTORE_PREVIOUS оставь как резервный контракт, но обычный путь не должен расходовать AI-вызов.

Перед применением каждого нового валидного AI-результата:
- previousMermaid = currentMermaid;
- currentMermaid = validatedMermaid.

При ошибке не меняй ни currentMermaid, ни previousMermaid.

Храни обе версии только в рамках текущей вкладки через существующий sessionStorage/session-state. Постоянную историю и отдельный UI истории не добавляй.

5. ВЛОЖЕНИЕ В ЧАТЕ

Поддержи одно вложение на сообщение размером до 10 МБ.

Используй существующий в проекте список допустимых текстовых, табличных, аудио- и видеоформатов как единый источник истины.

Обязательно:
- изображения не принимать;
- PDF принимать только с текстовым слоем;
- OCR не выполнять;
- до AI-запроса валидировать тип и размер;
- извлечь текст/табличное содержимое или получить транскрибацию;
- передать модели только ATTACHMENT_CONTEXT;
- не передавать бинарный файл внутрь prompt;
- не заменять исходное ТЗ содержимым вложения;
- при ошибке обработки не запускать AI и не менять схему;
- показывать понятную ошибку пользователю;
- во время активного запроса блокировать изменение вложения.

Проверь существующие ограничения и не создавай второй параллельный пайплайн обработки файлов.

6. ОТВЕТ МОДЕЛИ

Строгая JSON-схема:
{
  "mermaid": "string",
  "message": "string"
}

Дополнительные поля запрещены.

Frontend:
- использует mermaid только для визуальной схемы;
- никогда не показывает Mermaid-код в чате;
- выводит в чат только message.

7. ПРОВЕРКА И РЕМОНТ

До обновления схемы выполни:
- JSON schema validation;
- проверку запрещённых конструкций;
- Mermaid parse;
- Mermaid render с securityLevel strict;
- проверку ID, ссылок, class, style и subgraph;
- эвристики читаемости;
- проверку наложений по SVG bounding boxes, насколько это поддерживает текущая архитектура.

Если первая проверка не прошла:
- один раз вызвать repairMermaid.prompt.txt;
- повторить полный набор проверок.

Если повторная проверка не прошла:
- оставить текущую схему без изменений;
- не изменять previousMermaid;
- не сохранять candidate;
- вывести короткое сообщение без технических деталей.

8. АТОМАРНОЕ ОБНОВЛЕНИЕ

После успешной проверки одной операцией:
1. сохранить previousMermaid;
2. сохранить currentMermaid;
3. перерисовать схему;
4. добавить message в чат.

Не показывай message от невалидного ответа до завершения проверки Mermaid.

9. ОДИН АКТИВНЫЙ ЗАПРОС

Frontend:
- блокировать поле отправки;
- блокировать быстрые действия;
- блокировать прикрепление и удаление файла;
- показывать состояние выполнения.

Backend:
- использовать session lock и requestId;
- отклонять второй активный запрос одной сессии;
- не применять запоздалый ответ;
- освобождать lock даже при ошибке.

10. ТЕСТЫ

Добавь unit/integration tests:
- каждый actionType;
- три быстрых действия;

- RESTORE_PREVIOUS без AI-вызова;

- дополнительные поля в JSON;
- пустой message;
- Mermaid-код внутри message;
- запрещённый HTML/click/href/init;
- синтаксическая ошибка Mermaid;
- успешный repair;
- неуспешный repair;
- сохранение текущей схемы при ошибке;
- previousMermaid обновляется только после успеха;
- блокировка параллельного запроса;
- игнорирование запоздалого requestId;
- допустимое вложение;
- файл больше 10 МБ;
- неподдерживаемый тип;
- изображение;
- PDF без текстового слоя;
- ошибка извлечения;

Добавь e2e или компонентные сценарии:
1. Отправить текстовое изменение → получить message → схема перестроилась.
2. Нажать каждое быстрое действие → message появился → схема обновилась.
3. Прикрепить допустимый файл и отправить запрос → файл учтён → схема обновилась.
4. Получить невалидный результат → схема осталась прежней.
5. Написать «верни предыдущую версию» → предыдущая схема восстановилась без AI-вызова.
6. Во время выполнения повторная отправка и вложения недоступны.

11. КРИТЕРИИ ГОТОВНОСТИ

Задача завершена, когда:
- исходная генерация использует generateMermaid.prompt.txt;
- чат редактирует текущую схему, а не строит несвязанную новую;
- быстрые действия работают через actionType;
- текстовый запрос FREEFORM изменяет схему;
- вложение используется как дополнительный контекст;
- после успешной проверки одновременно появляются новая схема и message;
- при любой ошибке текущая схема сохраняется;
- фраза «верни предыдущую версию» восстанавливает предыдущий валидный Mermaid;
- Mermaid-код нигде не отображается пользователю;
- одновременно выполняется только один AI-запрос.

Не изменяй стартовую страницу, экспорт и остальную бизнес-логику, кроме необходимых точек интеграции.
