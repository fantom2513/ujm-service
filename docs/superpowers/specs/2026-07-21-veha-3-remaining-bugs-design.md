# Дизайн: Веха 3 — оставшиеся баги (#7, #10, #11, #13)

Дата: 2026-07-21
Статус: черновик на ревью

## Контекст и цель

Финальная веха плана фикса прод-багов CX Copilot
([[2026-07-20-cx-copilot-prod-bugfix-plan-design]]). Вехи 0, 1 и 2 завершены и
смержены в `main`. Эта веха закрывает оставшиеся 🔵/🟠-баги: #7 (аналитика
оценок/копирования), #10 (цвет иконки), #11 (выделенное состояние кнопки
рейтинга), #13 (скачивание вложения в чате по клику).

## Зафиксированные решения

- **#10 и #11 — общий корень.** SVG-иконки `thumb-up.svg`, `thumb-down.svg`,
  `copy-left.svg` (используются только в блоке действий под ответом
  ассистента, `ai-actions`) содержат `stroke="#152149" stroke-opacity="0.6"`,
  зашитый прямо в файл иконки, а не заданный через CSS/токен. Это ровно
  `rgba(21,33,73,0.6)` из #10. Из-за хардкода цвет невозможно переопределить
  через CSS для нажатого состояния — сейчас `aria-pressed="true"` меняет
  только `opacity: 0.8 → 1`, что и есть суть #11.
- **#13 — скачивание в рамках текущей сессии.** Реальный `File`-объект
  вложения нигде не персистится после отправки в чат (только метаданные
  `FileMeta` — name/format/size). Подтверждено с пользователем: скачивание
  ожидается только пока жива вкладка/сессия (File ещё в памяти); после
  перезагрузки страницы вложение остаётся некликабельным — это ожидаемое
  поведение, не баг, полноценное хранение файлов на backend — вне скоупа.
- **#7 — эндпоинт аналитики.** Ранее решено (мастер-план): свой внутренний
  endpoint без реального приёмника. Уточнено: на endpoint уходят и рейтинг
  (👍/👎), и клик по кнопке "Скопировать ответ".

## Находки, объясняющие корневые причины

### #10/#11 — иконки действий над ответом

`frontend/assets/icons/thumb-up.svg` (и thumb-down.svg, copy-left.svg)
содержат единственный `<path>` с атрибутом `stroke="#152149"
stroke-opacity="0.6"`. `svgIcon()` (`frontend/src/main.ts:494-498`) инлайнит
эти SVG в разметку как есть, только проставляя `class`. `.ai-actions button`
(`frontend/src/styles.css:1520-1541`) на `aria-pressed="true"` меняет лишь
`opacity`, но цвет самой иконки при этом не меняется, потому что цвет
зашит в атрибуте `stroke`, а не наследуется от `color`/CSS-переменной.

### #13 — вложение в чате не скачивается

`messageAttachmentCard()` (`frontend/src/main.ts:439-448`, рендерит
`.message-file-card`) — чисто декоративная разметка, без единого
`addEventListener`. Для сравнения, файл исходного ТЗ в шапке чата
(`sourceMessage()`, `frontend/src/main.ts:365-386`) уже поддерживает клик:
кнопка `data-source-download="true"` + модуль-уровня переменная `sourceFile:
File | undefined` + обработчик, вызывающий `downloadLocalFile(sourceFile)`
(`frontend/src/main.ts:691`). Для чат-вложений аналогичной связки File↔карточка
нет вообще — `chatFiles` (реальные `File[]`) очищаются сразу после отправки
(`chatFiles = []`, в `sendChat()`), а в `state.result.chat` попадает только
`FileMeta` через `attachment`/`attachments` на `ChatMessage`.

### #7 — аналитика оценок/копирования

`[data-feedback]`-обработчик (`frontend/src/main.ts:713-721`) и
`[data-copy-message]`-обработчик (`frontend/src/main.ts:725-731`) полностью
локальны — обновляют `message.feedback`/копируют в буфер, никуда не
отправляют событие. На backend нет вообще никакого кода, связанного с
аналитикой/фидбеком (подтверждено поиском по `backend/src`).

## Архитектура

Три независимые задачи.

### A. #10/#11 — цвет и выделенное состояние иконок

- `frontend/assets/icons/thumb-up.svg`, `thumb-down.svg`, `copy-left.svg`:
  заменить `stroke="#152149" stroke-opacity="0.6"` на `stroke="currentColor"`
  (единственное место использования каждой иконки — `ai-actions`, безопасно
  менять без побочных эффектов на другие экраны).
- `frontend/src/styles.css`, блок `.ai-actions button`
  (`frontend/src/styles.css:1520-1541`): добавить `color: var(--muted-soft)`
  по умолчанию (визуально тот же цвет, что и раньше, но теперь через
  существующий токен `--muted-soft: rgba(21, 33, 73, 0.5)` — ближайший
  существующий токен к текущему `rgba(21,33,73,0.6)`; сохраняем `opacity:
  0.8` на дефолтном состоянии как есть) и `color: var(--blue-bright)` на
  `.ai-actions button[aria-pressed="true"]` (используя существующий токен
  `--blue-bright: #2b5ce9`, уже применяемый для акцентных иконок в других
  местах интерфейса) — явная синяя заливка вместо едва заметной разницы в
  opacity.

### B. #7 — аналитика рейтинга и копирования

- Backend, новый модуль `backend/src/services/feedback/index.ts`: функция
  `recordFeedback(entry: FeedbackEntry): void`, где `FeedbackEntry = {
  messageId: string; kind: "rating" | "copy"; value?: "up" | "down";
  timestamp: string }`. На этом этапе — только структурированный
  `console.log` (задел на будущее переключение на реальный приёмник/БД, без
  реализации хранения сейчас).
- `backend/src/server/index.ts`: новый маршрут `POST /api/feedback`,
  валидирует `messageId` (непустая строка) и `kind` (`"rating"` требует
  `value` ∈ `{"up","down"}`; `"copy"` — `value` не нужен), при некорректном
  теле — `400`, иначе вызывает `recordFeedback` и отвечает `{ok: true}`.
- Frontend: `[data-feedback]`-обработчик (`main.ts:713-721`) и
  `[data-copy-message]`-обработчик (`main.ts:725-731`) дополнительно шлют
  fire-and-forget `fetch("/api/feedback", {...})` — не блокируют и не меняют
  существующий UI-поток; сетевые ошибки только логируются в консоль, не
  показываются пользователю (аналитика не должна мешать основному сценарию).

### C. #13 — скачивание вложения в чате по клику

- `frontend/src/main.ts`: новая модуль-уровня переменная `const
  messageFiles = new Map<string, File[]>();` (только в памяти, НЕ
  сериализуется в `sessionStorage`, в отличие от `state`).
- В `sendChat()`, сразу после создания `userMessage` (`main.ts:872-878`):
  `if (chatFiles.length) messageFiles.set(userMessage.id, [...chatFiles]);`
  (копия массива, т.к. `chatFiles` затем обнуляется).
- `messageAttachmentCard()` (`main.ts:439-448`): обернуть карточку в
  `<button type="button" data-message-file="${messageId}:${index}">`
  (составной ключ, т.к. у сообщения может быть несколько вложений) вместо
  текущего `<div>`, передавая `messageId` и индекс файла в разметку через
  параметры функции (потребуется изменить сигнатуру `messageAttachmentCard`,
  чтобы она принимала `messageId`/`index` — вызывающий код в `chatMessage()`
  тоже обновляется).
- Новый обработчик кликов (по аналогии с `[data-source-download]`):
  парсит `messageId`/`index` из `data-message-file`, ищет `messageFiles.get(messageId)?.[index]`,
  если найден — `downloadLocalFile(file)`; если нет (файл не в памяти,
  например после reload) — не делает ничего (карточка просто не реагирует,
  без ошибки).

## Тестирование

- A (#10/#11): визуальная проверка через headless-браузер (как в предыдущих
  вехах) — рендер сообщения с ответом ассистента, клик по 👍/👎, проверка
  вычисленного цвета SVG (`getComputedStyle`/`fill`/`stroke` через
  `currentColor` наследует от `color` кнопки) до и после нажатия — должен
  реально отличаться (не только opacity).
- B (#7): backend unit-тест на `POST /api/feedback` — валидные `rating`/`copy`
  payload'ы возвращают `200 {ok:true}`, невалидные (пустой `messageId`,
  `kind:"rating"` без `value`, `value` вне `up`/`down`) — `400`. Frontend —
  визуальная/сетевая проверка через headless-браузер: клик по 👍 инициирует
  запрос к `/api/feedback` с ожидаемым телом (перехват через CDP
  `Network`-домен или мок `fetch`).
- C (#13): headless-браузер — отправить сообщение с вложением, кликнуть по
  карточке вложения, убедиться что срабатывает скачивание (событие клика по
  синтетической ссылке/`Blob` URL создаётся); отдельно проверить, что после
  симуляции "потери" `messageFiles` (файл не в Map) клик по карточке не
  бросает ошибку и ничего не скачивает.

## Общие требования (сквозные, из исходного брифа)

- Не ломать поведение вне описанных багов, не трогать код вне зоны бага.
- Минимум один regression-тест на пункт.
- Цвета выносятся в существующие токены (`--muted-soft`, `--blue-bright`), не
  хардкодятся заново.
- После вехи — краткое summary изменённых файлов и добавленных/обновлённых
  тестов.

## Технический долг / открытые вопросы

- `--muted-soft` (`rgba(21,33,73,0.5)`) не идентичен исходному
  `rgba(21,33,73,0.6)` — визуальная разница минимальна (0.5 vs 0.6 opacity
  на тёмно-синем), решено переиспользовать существующий токен вместо
  добавления нового ради разницы в 0.1 прозрачности; если после визуальной
  проверки разница будет заметна, можно завести отдельный токен — решается в
  задаче A.
- #7's `recordFeedback` — временная реализация (console.log), без
  персистентности/БД; переключение на реальный приёмник — отдельная будущая
  задача, не блокирует эту веху.
