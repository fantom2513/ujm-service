## Контекст

Источник — таблица багов из UI/UX-ревью в Figma (27 пунктов, 14 со статусом «нужно исправить»). Разбивка по типу и файлам сделана ресёрчем, полностью — в истории чата; здесь только то, что относится к этой партии.

Прод сейчас работает на legacy `backend/src` + `frontend/src` (не `backend-py`) — все файлы ниже оттуда.

Не в этой партии:
- **№5, 15, 20, 22, 27** — промпт/структурная валидация Mermaid, вынесены в `.intern/08-mermaid-structural-validation.md` и `.intern/09-mermaid-prompt-reliability.md` (задачи для стажёра).
- **№21** — «текстовый запрос → ошибка загрузки файла». Проверил гипотезу «как №12» (несброшенный `chatFiles`) — не подтвердилась: `sendChat()` намеренно не чистит вложение при ошибке (та же логика, что восстановление черновика текста). Раз `attachment-error` шлёт бэкенд, а не фронт его путает — нужна живая репродукция, фикса пока нет.
- **№14** — скролл списка вложений. По коду (`styles.css:1707-1727`) скролл технически доступен (жестом/колесом), просто скрыт скроллбар. Раньше не воспроизводилось (`docs/HANDOFF.md:129`). Нужна живая проверка, не статический фикс.
- **№19** — пропорции PNG при экспорте. Гипотеза есть (`export.ts:50-58`, фоллбэк на захардкоженные `SVG_WIDTH/HEIGHT`, когда у SVG нет атрибутов `width`/`height`), но не подтверждена в браузере — нужно посмотреть, что реально отдаёт mermaid@11 через CDN.
- **№10** — цвет иконок. `--muted` используется и текстом, и частью иконок; большинство иконочных классов (`.nav-icon`, `.quick-icon`, `.control-icon`) вообще не задают цвет сами. Нужен скрин конкретно «макет vs текущий вид», чтобы не задеть заодно обычный текст.

## №12 — фантомный файл при возврате на стартовую страницу

**Баг:** после «Создать новую схему» из модалки схема строится по старому файлу, хотя UI показывает пустой аплоадер.

**Причина:** `main.ts:683-694`, обработчик `#modal-confirm`. Сбрасывается `state = structuredClone(defaultState)`, но не сбрасываются модуль-level переменные `selectedFile`, `sourceFile`, `chatFiles`, `messageFiles` — они не часть `AppState`. `validateBeforeSubmit()` (main.ts:993) пропускает проверку «файл обязателен», потому что `selectedFile` всё ещё истинный.

**Фикс:** в этом же обработчике, до `persist()`, сбросить все четыре: `selectedFile = undefined; sourceFile = undefined; chatFiles = []; messageFiles.clear();`. Одна причина (module-level state не входит в `AppState`-ресет), четыре места — чиним разом.

**Файлы:** `frontend/src/main.ts`.

## №23 — статичный статус «Анализирую»

**Баг:** во время ответа ассистента текст статуса не меняется, ощущается «зависшим».

**Причина:** `main.ts:432-434`, `generatingMessage()` — жёстко захардкоженный текст без ротации.

**Фикс:** список фраз (`«Анализирую»`, `«Думаю…»`, `«Вношу правки…»`, `«Секунду, обновляю схему…»`), ротация раз в ~2.5с через `setInterval`, который точечно обновляет `textContent` у `.message-generating span` (не гоняет весь `render()`, чтобы не сбрасывать скролл/фокус). Старт — сразу после `render()` в `sendChat()` (main.ts:922), очистка интервала — в `finally` (main.ts:963-967). Textarea задизейблена на время загрузки, так что риск конфликта с обычным re-render минимален.

**Файлы:** `frontend/src/main.ts`.

## №24 — тост без закрытия + ошибка переживает reload

Два независимых фикса на одном экране (подтверждено скрином 7 — тост с крестиком, который не работает).

**24a. Кнопка закрытия тоста не работает.** `generationToast()` (main.ts:495-503) рендерит кнопку `aria-label="Закрыть"` без обработчика — прогрепал весь `bindEvents()`, привязки нет вообще.
Фикс: добавить обработчик клика — сбрасывает `state.start.error`, ре-рендер.

**24b. Reload не решает проблему.** `File`-объекты не переживают `sessionStorage` (не сериализуются), а `state.start.error`/`state.start.file` — переживают (`state/session.ts:24-32`, `loadState()` мержит сохранённое поверх `defaultState`). После reload UI показывает старую ошибку и/или «прикреплённый» файл, а `selectedFile` уже `undefined` — повторная попытка гарантированно проваливается тем же образом, крутится по кругу.
Фикс: в `loadState()` — если восстановлен `start.file`, реального `File` за ним нет и быть не может (это всегда так после reload) → сразу чистить `start.file` и `start.error` с `field === "attachment"`, чтобы UI честно показывал «файл не прикреплён» и просил прикрепить заново, а не зацикливался на ошибке, которую нечем повторить.

**Файлы:** `frontend/src/main.ts`, `frontend/src/state/session.ts`.

## №25 — «странный артефакт» под чатом + непонятная ошибка

**Баг (подтверждено скрином 6):** в чат как сообщение ассистента прилетает сырой `Unexpected token '<', "<!DOCTYPE "... is not valid JSON`, отдельно висит «бомба» mermaid.js с `Syntax error in text`.

**Причина — три независимых утечки в одном сценарии:**
1. `api/client.ts:5,19` — `response.json()` без try/catch. Если бэкенд/прокси в ответ на таймаут/502 отдаёт HTML вместо JSON, `.json()` кидает сырой `SyntaxError`.
2. `main.ts:1201-1204`, `normalizeApiError()` — проверка `"message" in error` слишком широкая: у `SyntaxError` тоже есть `.message`, поэтому он проходит как «валидный» `ApiError` и его сырой текст уходит прямо в чат вместо дружелюбного фолбэка.
3. `utils/export.ts:21` — `mermaid.initialize()` без `suppressErrorRendering: true`. При невалидном Mermaid-коде mermaid.js сам вставляет в DOM собственную «бомбу» — это и есть «артефакт под чатом», независимо от нашего catch в `renderMermaid()` (export.ts:33-36).

**Фикс:**
- `requestJson()`/`getConfig()` в `api/client.ts` — обернуть `response.json()` в try/catch, при не-JSON ответе бросать нормальный `ApiError` (например, `{code: "network-error", message: "..."}"`) вместо сырого `SyntaxError`.
- `normalizeApiError()` — ужесточить guard: требовать ещё и `"code" in error`, не только `"message"`, чтобы посторонние `Error`/`SyntaxError` не проходили как валидный `ApiError`.
- `getMermaid()` в `export.ts` — добавить `suppressErrorRendering: true` в `mermaid.initialize()`.

**Файлы:** `frontend/src/api/client.ts`, `frontend/src/main.ts`, `frontend/src/utils/export.ts`.

## №26 — задвоенная ошибка загрузки файла

**Баг (подтверждено скрином 8):** «Конкурсы.pdf / Не удалось загрузить файл» в строке вложения + отдельно «Ошибка загрузки файла» под ней — одновременно.

**Причина:** `attachmentRow()` (main.ts:232-259) хардкодит `"Не удалось загрузить файл"` как `detail`, когда `status === "error"`, игнорируя реальный текст. `uploadSource()` (main.ts:181-211) отдельно рендерит настоящий `state.start.error.message` в `<em class="inline-error">` сразу под строкой вложения.

**Фикс:** прокинуть реальный `error` (уже вычисленный в `uploadSource()`) параметром в `attachmentRow()` и использовать его как `detail` вместо хардкода; убрать отдельный `<em class="inline-error">` в `uploadSource()`, чтобы не дублировать один и тот же текст дважды.

**Файлы:** `frontend/src/main.ts`.
