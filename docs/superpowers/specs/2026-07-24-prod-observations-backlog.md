## 1. Сохранение схемы / сессии между заходами

**Симптом:** после закрытия вкладки результат теряется — контекст живёт только в
`sessionStorage` (см. `state` в `frontend/src/main.ts`, ключ `copilot-mermaid-session-v1`).

**Причина:** серверных сессий/персистентности нет by design в TS-скелете. Это
«Дыра №1», явно вынесенная в **Фазу 2** Python-плана (сессии + контекст чата в
Postgres/Redis).

**Подход (Python):**
- Модель сессии: `session_id`, исходник, текущий/предыдущий mermaid, история чата, timestamps.
- Хранилище: Postgres (persist) + Redis (горячий кэш активной сессии), как в infra-design.
- API: `POST /api/sessions` (создать), `GET /api/sessions/{id}` (восстановить), автосейв на каждое изменение схемы/сообщение.
- Фронт: при загрузке результата тянуть по `session_id` из URL, а не только из `sessionStorage`.

**Зависимости:** блокируется Фазой 0–1 Python (скелет + БД). Самый крупный пункт.

## 2. Роутинг «На главную» / закрытие схемы

**Симптом:** на странице результата кнопка «На главную» (`#go-home`) открывает
модалку и по подтверждению уводит на `state.config.productHomeUrl`, который сейчас
= `http://localhost:3000/` (дефолт из `/api/config`, `backend/src/config/index.ts` →
`PRODUCT_HOME_URL`). На проде это выглядит как «просто показывает localhost:3000».

**Где в коде:**
- `frontend/src/main.ts:269` — кнопка `#go-home`.
- `frontend/src/main.ts:688-689` — `window.location.href = state.config.productHomeUrl`.
- `backend/src/config/index.ts` — `productHomeUrl` (env `PRODUCT_HOME_URL`).

**Подход:**
- Прод: задать `PRODUCT_HOME_URL` на реальный хост продукта (не дефолт).
- Продумать роутинг: должна ли «На главную» вести на внешний продукт или на стартовую
  страницу самого сервиса (выбор источника). Сейчас стартовая и результат — это SPA-состояния
  без настоящих URL; при переносе стоит завести реальные маршруты (`/`, `/result/{session_id}`),
  чтобы «закрыть схему» = вернуться на `/`, а не на внешний `localhost:3000`.
- Уточнить у продукта ожидаемое поведение перед реализацией.

## 3. Стрелки не присоединяются к блокам

**Симптом:** на части сгенерированных схем некоторые стрелки «висят» — не стыкуются
с узлами.

**Вероятные причины (проверить):**
- LLM генерирует ребро на узел с чуть иным ID, чем объявленный, — Mermaid молча создаёт
  пустой узел, и визуально стрелка «не туда».
- Спецсимволы/кириллица в ID узлов.
- Особенности клиентского рендера Mermaid (версия с CDN, `mermaid.esm.min.mjs`).

**Где в коде:**
- Валидатор `backend/src/services/mermaid/index.ts` сейчас проверяет только заголовок
  `flowchart <DIR>` и запрещённые паттерны — связность графа не проверяется.
- Промпты генерации/правки — `backend/src/prompts/`.

**Подход:**
- Добавить структурную валидацию: все узлы в рёбрах должны быть объявлены; ловить
  «сиротские» ID. Это прямо ложится в **Tier 2/3** роадмапа
  [`2026-07-22-mermaid-validation-pipeline-roadmap.md`](2026-07-22-mermaid-validation-pipeline-roadmap.md).
- Усилить промпт: явно требовать объявления всех узлов перед рёбрами, единый стиль ID.
- Задействовать repair-путь (как в `chatEdit`) и для `generateDiagram` (это уже отмечено
  как #11 Tier 1 в роадмапе).
- Собрать 2–3 реальных примера «битых» схем с прода для регресс-тестов.

## 4. Кнопка «вернуть прошлую версию» в чате

**Симптом:** пользователь хочет кликом откатывать схему к предыдущему варианту, а не
только текстом.

**Что уже есть (бэкенд готов):**
- `backend/src/server/index.ts` — `UNDO_PHRASES` + `normalizeUndoMessage`: фразы отмены
  распознаются и мапятся в `RESTORE_PREVIOUS`.
- Поддержка `previousMermaidCode` в `/api/chat`: сервер умеет вернуть предыдущую схему.
- `frontend/src/main.ts:48` — тип действия `RESTORE_PREVIOUS` уже заведён.

**Чего не хватает (фронт):**
- UI-кнопка «Вернуть прошлую версию» (быстрое действие или иконка у сообщения),
  отправляющая `actionType=RESTORE_PREVIOUS` без необходимости печатать фразу.
- Желательно — история версий (стек), чтобы возвращаться на несколько шагов, а не только на 1.

**Подход:** начать с одной кнопки (откат на 1 шаг, backend уже поддерживает); стек
версий — вторым этапом, вместе с сохранением сессий (п.1).

## 5. Копирование сообщений пользователя

**Симптом:** скопировать можно только ответы ассистента.

**Где в коде:**
- `frontend/src/main.ts:467-472` — `aiMessageActions()` рендерит `data-copy-message`
  **только для ответов ассистента**.
- `frontend/src/main.ts:750-752` — обработчик копирования привязан к `[data-copy-message]`.

**Подход:** добавить кнопку копирования и к бабблам пользователя
(`chatMessage()` / `.message.user`), переиспользовав существующий обработчик копирования.
Небольшая фронтовая правка.

## 6. Быстрые подсказки пропадают после первого сообщения

**Симптом:** быстрые действия («Выделить основной путь», «Разбить на смысловые блоки»,
«Упростить») показываются только до первого сообщения, потом исчезают.

**Причина (найдена):**
- `frontend/src/main.ts:340` — `result.chat.length || isChatLoading ? "" : quickActions()`:
  как только в чате появляется хоть одно сообщение, `quickActions()` перестаёт рендериться.

**Где в коде:**
- `frontend/src/main.ts:415` — `quickActions()`.
- `frontend/src/main.ts:425-428` — `quickActionType(label)` (маппинг по русскому тексту
  кнопки → тип действия; это же #14 Tier 1 в mermaid-роадмапе — заменить на `data-quick-action`/enum).

**Подход:**
- Показывать быстрые действия и после начала диалога (например, компактной строкой над
  полем ввода), а не только на «пустом» экране.
- Заодно уйти от сравнения русского текста в `quickActionType` на `data-quick-action`
  (устойчивее к локализации, закрывает #14 из роадмапа).
