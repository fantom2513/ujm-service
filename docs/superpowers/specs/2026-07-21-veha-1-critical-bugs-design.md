# Дизайн: Веха 1 — критичные прод-баги (#1, #2/mojibake, #8, #12)

Дата: 2026-07-21
Статус: черновик на ревью

## Контекст и цель

Продолжение плана фикса прод-багов CX Copilot
([[2026-07-20-cx-copilot-prod-bugfix-plan-design]]). Вехи 0 (контекст чата +
usage-трекинг) и 2 (синхронизация промптов + фикс модалки #16) завершены и
смержены в `main`. Эта веха закрывает оставшиеся 🔴-баги: #1, #2, #8, #12, а
также ранее обнаруженный (вне исходного брифа) баг с кракозябрами в именах
файлов, который в ходе расследования оказался тем же багом, что и #2.

## Зафиксированные решения

- **#2 = mojibake.** Скрин, изначально приложенный к #2 ("имя файла не всегда
  передаётся в чат"), показывает имя файла НЕ отсутствующим, а нечитаемым
  (кракозябры). Это тот же баг кодировки filename, что и отдельно обнаруженный
  mojibake-баг — закрывается одним фиксом.
- **#1 и mojibake — независимые баги**, не общий корень, несмотря на то что на
  одном из скринов проявились одновременно (зависшая заглушка схемы + битое
  имя вложения в одной и той же сессии). Чинятся отдельными фиксами в разных
  частях кода (frontend state-restore vs backend multipart-парсинг).
- **#8 и #12** — на момент дизайна есть только гипотезы корневой причины (см.
  ниже), не подтверждённые фактическим воспроизведением. По аналогии с #14/#17
  из Вехи 2 — расследование до конкретного фикса происходит внутри
  соответствующей задачи имплементационного плана, а не предрешается здесь.

## Находки, объясняющие корневые причины

### #1 — схема не подгружается при возврате в чат/навигации/refresh

Подтверждённый сценарий: и навигация назад, и обновление страницы (F5).

Корень: `cachedSvg` в `frontend/src/utils/export.ts` — module-level
переменная в памяти, не персистентная. Она заполняется только внутри
`renderMermaidAndUpdate()` (`frontend/src/main.ts:812-820`), которая
вызывается лишь сразу после успешного `generateDiagram`/`sendChatMessage`
(`main.ts:850`, `main.ts:917`). На старте скрипта вызывается только `render()`
(`main.ts:1204`), а на `popstate` — `state = loadState(); render()`
(`main.ts:1200-1203`). Ни один из этих путей не вызывает
`renderMermaidAndUpdate` повторно. `render()` перерисовывает HTML-каркас
result-страницы (включая пустой `#diagram-content`), но реальный SVG туда
никогда не попадает — виден только фолбэк `fallbackSvg()` из `export.ts:41`
("Схема загружается..." навсегда).

### #2 / mojibake — кракозябры в имени файла

`parseMultipart()` (`backend/src/server/index.ts:76-80`) декодирует весь
буфер запроса как `latin1` (строка 68: `raw = buffer.toString("latin1")`) —
это нужно, чтобы найти границы multipart-частей по байтам. Значения полей
формы корректно перекодируются обратно в UTF-8 при извлечении
(`Buffer.from(bodyText, "latin1").toString("utf8")`, строка 91). Но `filename`
(строка 80, `disposition[2]`) берётся из уже latin1-декодированной строки
заголовка напрямую, без обратного перекодирования — отсюда кракозябры для
любого не-ASCII имени файла (кириллица и т.п.).

### #8 — PNG-экспорт не работает (гипотеза, требует подтверждения в задаче)

`downloadPng()` (`frontend/src/utils/export.ts`) грузит SVG через
`URL.createObjectURL` → `<img>` → `canvas.drawImage` → `canvas.toBlob()`.
Mermaid-схемы нередко содержат `<foreignObject>` (HTML-лейблы внутри SVG) —
известная проблема связки Mermaid+Canvas-экспорт: canvas, отрисованный из SVG
с `foreignObject`, считается tainted, и `toBlob`/`toDataURL` падает с
SecurityError. Подтверждается/опровергается воспроизведением с реальной
mermaid-схемой в задаче.

### #12 — генерация без файла молча (гипотеза, требует расследования в задаче)

`validateBeforeSubmit()` (`frontend/src/main.ts:951-962`) блокирует сабмит без
файла для всех трёх `sourceType` ("text-file", "recording", "link") на
клиенте. Backend (`handleGenerate`, `backend/src/server/index.ts:129,147`)
также проверяет `!file || !file.filename` для "text-file"/"recording". На
первый взгляд оба уровня должны блокировать сценарий "генерация вообще без
файла" — сценарий, который пользователь подтвердил как воспроизводимый,
значит, либо есть путь в обход обеих проверок (например, гонка состояния
`selectedFile` между валидацией и сборкой `FormData`), либо баг проявляется не
в основной генерации, а в chat-вложениях (`handleChat`, строка 272 —
`attachment` там опционален по дизайну, и это может быть источником путаницы
с #12, если ожидание пользователя было другим). Точный сценарий — предмет
расследования в задаче.

## Архитектура

Четыре независимые точечные задачи, без общей инфраструктуры:

### A. #1 — восстановление рендера схемы

- `frontend/src/main.ts`: выделить общую функцию `restoreResultView()`,
  вызывающую `renderMermaidAndUpdate(state.result.mermaidCode)`, если
  `state.page === "result" && state.result`. Вызывать её из:
  - точки входа скрипта (после первого `render()` при старте, вместо/в
    дополнение к нему);
  - обработчика `popstate` (после `state = loadState(); render()`).
- Не требует изменений на backend.

### B. #2/mojibake — фикс кодировки filename

- `backend/src/server/index.ts`, `parseMultipart()`: заменить
  `const filename = disposition[2];` на перекодирование, аналогичное полям:
  `const filename = disposition[2] ? Buffer.from(disposition[2], "latin1").toString("utf8") : undefined;`
- Не требует изменений на frontend (имя уже передаётся и отображается
  корректно, если сервер отдаёт правильные байты).

### C. #8 — PNG-экспорт

- Задача начинается с воспроизведения: сгенерировать реальную mermaid-схему
  (в т.ч. с `HIGHLIGHT_MAIN_PATH`/decision-узлами, где вероятны
  `foreignObject`-лейблы) и попытаться экспортировать в PNG в headless-браузере,
  зафиксировать точную ошибку/поведение.
- Если подтверждается tainted-canvas: обойти через явную сериализацию SVG
  (`XMLSerializer`) в `data:` URI вместо `blob:` URL, и/или удаление/замену
  `foreignObject`-контента на чистый SVG `<text>` перед растеризацией (если
  визуально приемлемо), и/или явную установку `crossOrigin`/убрать источник
  "нечистоты". Конкретный метод обхода фиксируется по результатам
  воспроизведения — не предрешается здесь.

### D. #12 — молчаливая генерация без файла

- Задача начинается с воспроизведения нескольких кандидатов-сценариев:
  прямой вызов `/api/generate` без файла в обход фронтовой валидации;
  гонка `selectedFile`/`FormData` во время сабмита; путаница с опциональным
  chat-вложением в `handleChat`.
- По результатам — добавить недостающую защиту на том уровне, где она
  реально отсутствует (backend не должен полагаться только на фронтовую
  валидацию — если найдётся путь, где `handleGenerate` создаёт схему без
  корректного `source`, там нужна дополнительная проверка).

## Тестирование

- A (#1): backend не затрагивается; frontend — визуальная/e2e проверка через
  headless-браузер (как в Вехе 2): сгенерировать схему → перезагрузить
  страницу / имитировать `popstate` → убедиться, что SVG (не заглушка)
  отображается сразу.
- B (#2/mojibake): unit-тест на `parseMultipart` — не-ASCII (кириллица)
  filename в multipart-запросе должен вернуться корректной UTF-8 строкой, не
  битой.
- C (#8): регрессионный тест/сценарий — экспорт PNG для схемы с
  `foreignObject`/decision-узлами не должен падать; проверить в headless-
  браузере, что итоговый PNG не пустой (реальный byte-check размера/сигнатуры
  файла, не только отсутствие исключения).
- D (#12): после того как сценарий воспроизведён — regression-тест именно на
  найденный сценарий (unit на backend-валидацию и/или e2e на фронт).

## Общие требования (сквозные, из исходного брифа)

- Не ломать поведение вне описанных багов, не трогать код вне зоны бага.
- Минимум один regression-тест на пункт (для C/D — по итогам расследования,
  тест пишется на подтверждённый сценарий, а не на гипотезу).
- После вехи — краткое summary изменённых файлов и добавленных/обновлённых
  тестов.

## Технический долг / открытые вопросы

- Точный сценарий #12 неизвестен до расследования в задаче — риск, что найдётся
  не один, а несколько независимых путей воспроизведения; в этом случае
  решается по одному правки на найденный путь, ситуация фиксируется в отчёте
  по задаче.
- #8: если корень не в `foreignObject`, а в чём-то ещё (например, CORS у
  внешнего mermaid CDN-скрипта, влияющий на "чистоту" canvas) — обход может
  потребовать более широкого решения (например, локальный бандл mermaid
  вместо CDN); это будет решаться по факту в задаче, не предрешается здесь.
