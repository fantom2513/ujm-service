## 1. Что это за сервис

Веб-сервис генерации и редактирования Mermaid-схем пользовательских путей (UJM):
пользователь загружает источник (текстовый файл / запись / ссылку), сервис через
LLM (vLLM, OpenAI-совместимый API) генерирует flowchart-схему, дальше её можно
править в чате свободным текстом или quick-action кнопками.

**Текущий стек (legacy, подлежит замене):**

- Backend: Node 24 + TypeScript через нативный type-stripping (без сборки), ~15 файлов в `backend/src`
- Frontend: vanilla TypeScript + Vite, `frontend/src` (рендер Mermaid — только на клиенте, `mermaid.esm.min.mjs` с CDN)
- Тесты: `node:test` + `node:assert/strict`, 73 теста, все зелёные
- Деплой: Docker + GitLab CI, `docker-compose.prod.yaml`
- Хранилища: **нет** — ни БД, ни Redis, ни серверных сессий

**Ключевые каталоги:**

```
backend/src/
  server/            HTTP-роутинг, multipart-парсер, handleGenerate/handleChat
  services/openai/   промпт-сборка (prompts.ts), generateDiagram, chatEdit
  services/mermaid/  validateMermaid()
  services/files/    парсеры docx/pdf
  services/feedback/ внутренний приёмник оценок
  infrastructure/llm/ VLLMClient: retry, response_format fallback, TLS, usage
  prompts/           *.prompt.txt — единственный источник правды для системных промптов
frontend/src/        main.ts (весь UI-стейт), styles.css, utils/export.ts
docs/superpowers/
  specs/             дизайн-документы по вехам
  plans/             пошаговые планы реализации
```

## 4. Как здесь принято работать

Соблюдение этих соглашений — не формальность, по ним построена вся история репозитория.

**Процесс:** дизайн-спека → пошаговый план → реализация по плану → тесты → коммит на задачу.

- Спеки: `docs/superpowers/specs/YYYY-MM-DD-<тема>-design.md` — контекст, зафиксированные
  решения, находки о корневых причинах, архитектурные изменения, открытые вопросы.
- Планы: `docs/superpowers/plans/YYYY-MM-DD-<тема>.md` — задачи с явными шагами,
  файлами, командами и точками «запусти тест, ожидай FAIL/PASS».
- Кросс-ссылки между документами — через `[[имя-файла-без-расширения]]`.

**Код:**

- TDD: сначала падающий тест, потом реализация. Регрессионный тест — минимум один на баг.
- Один коммит = одна задача. Сообщение — `fix:`/`feat:`/`docs:`/`test:` + суть + `(#N)` номера багов.
- Не трогать код вне зоны задачи.
- Цвета и стилевые константы — в токены (`styles.css` переменные / mermaid `classDef`), не хардкодом по месту.
- Промпты правятся **только** в `backend/src/prompts/*.prompt.txt`, никаких констант в коде.

**Проверка:**

```bash
npm test                      # 73 теста (node --test из корня)
```

Фронтового тест-раннера нет; фронт проверялся вручную и через CDP-скрипты
(паттерн описан в `docs/superpowers/plans/2026-07-21-veha-1-critical-bugs.md`, Task 2 Step 4).
Если фронт остаётся на TS — заведение нормального фронтового тест-раннера
(Vitest + jsdom) стоит первым пунктом.

## 5. Куда двигаться: переход на Python

Полный дизайн зафиксирован в
[`2026-07-10-python-backend-infra-design.md`](superpowers/specs/2026-07-10-python-backend-infra-design.md).
Кратко, чтобы не открывать спеку ради общей картины:

**Почему.** Команда живёт на Python/Go и не будет поддерживать TS долгосрочно.
Плюс у сервиса вообще нет инфраструктурного слоя: нет БД, сессий, истории, кэша.

**Как.** Новый `backend-py` на **FastAPI (async)**, контракт `/api/*` сохраняется
1:1 (`/health`, `/config`, `/generate`, `/chat`) — **фронт не трогаем**. Сборка
поэтапная, выкат — единым cutover после тестирования текущей TS-версии;
параллельного strangler'а в проде нет.

**Слои:**

```
api/                роутеры + Pydantic-схемы (контракт /api)
domain/             нормализация источников, mermaid-валидация, промпт-логика
infrastructure/llm/ порт LLM-клиента: retry, fallback response_format
                    (json_schema → json_object → none), insecure-TLS — перенос из TS 1:1
infrastructure/store/ репозитории Postgres + Redis за абстракцией Cache
services/files|links|recordings/  парсеры и заглушки
```

**Инфраструктура.** Postgres — per-product, свой контейнер в этом репо
(`sessions`, `messages`, `diagram_versions`). Redis — общий из инфра-репо платформы
`cx_copilot`, свой логический DB-номер + префикс ключей `uxarch:` (кэш LLM-ответов,
горячие снапшоты сессий, распределённые локи). RabbitMQ — **отложен** до появления
реальной STT-модели. Auth — только заготовка: identity из заголовка gateway → `user_id`.

**Фазы (в порядке приоритета):**

| Фаза | Содержание |
|---|---|
| 0 | Каркас FastAPI + Docker + Postgres/Redis + паритет `/health`, `/config`, CI |
| 1 | LLM-слой + `/generate` (паритет с TS: retry / TLS / fallback) |
| **2** | **Сессии + контекст чата + история (`/chat` с диалогом) — главный приоритет** |
| 3 | Кэш (LLM-cache, горячие сессии) + заготовка auth |
| 4 | Парсеры (XLSX через `openpyxl`) + реальный Jira/Confluence-коннектор; `recordings.transcribe()` как заглушка |
| 5 | Примирение спек-дрейфа mermaid-валидации, прод-логи без пользовательских данных, e2e + cutover |
| 6 | Отложено: RabbitMQ + воркер + реальная транскрибация (Whisper) |

**Открытый вопрос, требующий решения до Фазы 2:** серверная сессия через
httpOnly-cookie `session_id` (фронт не трогаем — рекомендация спеки) против явного
`session_id` в теле запроса (правки фронта, но сразу открывает возможность истории в UI).

**Что переносить дословно, а что переосмыслить:**

- Переносить 1:1: поведение `VLLMClient` (retry, fallback по `response_format`, TLS,
  парсинг `usage`), логику `validateMermaid`, содержимое `*.prompt.txt` (копировать
  файлы как есть — это авторский контент, а не код).
- Переосмыслить: оконная история чата — на сервере из БД вместо клиентского
  `sessionStorage`; лок «один AI-запрос за раз» — распределённый Redis-лок по
  `session_id` вместо фронтового `isChatLoading`; repair-путь — единый для generate и edit.
- Не тащить: `previousMermaid` как отдельное поле — его заменяет таблица `diagram_versions`.

**Заглушки, которые останутся заглушками и после cutover:** транскрибация (нет STT-модели),
история-UI на фронте (требует правок фронта — поздняя фаза).
